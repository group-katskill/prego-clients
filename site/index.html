Prego clients

Client tools for Prego registries: crates, OCI images, Go modules and npm packages. They find the machine identity of your build, exchange it at the Prego STS, and give Cargo, Docker and other tools a registry token that is valid for 15 minutes by default. No long-lived secret goes into your config.

Install Source on GitHub

Cargo 1.74 or later. Linux and Apple silicon macOS binaries on every release.

shell
$ cargo install cargo-credential-prego docker-credential-prego prego
# CI: GitLab id_tokens, GitHub OIDC, SPIFFE or an API key
$ cargo build --locked
  Downloaded acme-core v1.4.2 (registry `acme`)
$ prego setup docker --write
$ docker push oci.prego.k8skill.com/acme/default/api:1.4.0

The tools

  • binary

    cargo-credential-prego

    Cargo credential provider. Cargo runs it to get a token for a Prego crate registry.

  • binary

    docker-credential-prego

    Docker credential helper. Docker, Podman, BuildKit, crane, ORAS and Helm run it to sign in to the Prego OCI registry.

  • binary

    prego

    CLI: prego whoami, prego token, prego setup cargo|docker|go, prego oci push for layers above 95 MiB, and from 0.4.0 prego go publish and the GOAUTH helper prego go-auth.

  • library

    prego-auth

    Identity sources, the settings file, the STS exchange and the OCI token realm. All tools use it.

How it works

  1. 01

    A tool asks

    Cargo or Docker starts the Prego tool when it needs a token for your Prego registry.

  2. 02

    Find an identity

    The tool finds a subject token: a JWT-SVID, a CI OIDC token, a token file or an API key.

  3. 03

    Exchange at the STS

    It sends the subject token to the Prego STS (RFC 8693). Your tenant's trust config decides.

  4. 04

    Short-lived token

    The registry token is valid for 15 minutes by default (5 to 30 minutes per grant). The tools get a new one before it expires. For images, the identity goes only to the Prego token realm.

Install

The install script puts all three tools in ~/.local/bin. It checks the SHA-256 sums and never uses sudo:

$ curl -fsSLO https://github.com/group-katskill/prego-clients/releases/latest/download/install.sh
$ sh install.sh                    # or: sh install.sh --version 0.10.0

Or from crates.io (all five crates are at 0.10.0, with the alias prego-cli):

$ cargo install cargo-credential-prego docker-credential-prego prego

Each release has prego-clients-<target>.tar.gz with all three tools, one archive per tool, and a .sha256 file for each archive.

Targets

TargetNotes
x86_64-unknown-linux-muslStatic. No OpenSSL.
aarch64-unknown-linux-muslStatic. No OpenSSL.
aarch64-apple-darwinApple silicon. Not code-signed or notarized by Apple. No Intel macOS build.

TLS uses rustls with the Mozilla root set. --version prints the version and the git commit.

Verify a release

From 0.3.0, SHA256SUMS is signed with cosign (keyless, the GitHub Actions identity of the release workflow). Check the signature, then the sums: 

$ cosign verify-blob SHA256SUMS \
    --bundle SHA256SUMS.sigstore.json \
    --certificate-identity https://github.com/group-katskill/prego-clients/.github/workflows/release.yml@refs/tags/prego-clients-v0.7.0 \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
$ sha256sum --ignore-missing -c SHA256SUMS

Log in on a laptop

From 0.7.0, log in with your own console account. No key is stored in a file:

$ export PREGO_TENANT=acme PREGO_EDGE_CODE=k7mq
$ prego login            # confirm the code at app.prego.k8skill.com/device. --publish to publish too
$ prego status           # tenant, access and end time. Never a token

Then set up each tool as below. Cargo, Docker, Go and npm use the session when no workload identity and no PREGO_API_KEY is set. The session is kept in your OS keychain (on Linux without a desktop, in the kernel keyring, lost at reboot), never in a plain file. It ends after 7 days without use, after 30 days in all, or with prego logout. CI never uses prego login: see the CI guide.

prego login prints a code. Confirm it at app.prego.k8skill.com/device while you are signed in to the console. A login with --publish asks for your passkey there.

Lost laptop? Revoke its session in the console: Settings, Your sessions.

Configure Cargo

Replace acme with your tenant slug, and default with your namespace. From 0.6.0, also set your tenant's edge code (the console shows it): edge_code = "k7mq" in ~/.config/prego/config.toml, or PREGO_EDGE_CODE.

.cargo/config.toml
[registries.acme]
index = "sparse+https://cargo.prego.k8skill.com/t/acme/default/index/"
credential-provider = ["cargo-credential-prego", "--tenant", "acme"]
ArgumentEnvironmentDefault
--tenant <slug>PREGO_TENANTrequired
--sts-url <url> PREGO_STS_URL https://sts.prego.k8skill.com/v1/sts/token (registry tokens at /v1/sts/token/e/<edge code>)
--edge-code <code>PREGO_EDGE_CODErequired (the console shows it)
--audience <aud>PREGO_AUDIENCEprego.k8skill.com
--source <name>PREGO_SOURCEauto
nonePREGO_CA_FILEnone (extra PEM CA bundle)

Push and pull images

The Prego OCI registry is oci.prego.k8skill.com. Image names are <tenant>/<namespace>/<repo>:<tag>. Set the tenant in ~/.config/prego/config.toml, then add the helper:

shell
$ prego setup docker --write   # adds credHelpers to ~/.docker/config.json
$ docker push oci.prego.k8skill.com/acme/default/api:1.4.0
# a layer above 95 MiB: push it in parts
$ docker save acme-api:1.4.0 -o api.tar
$ prego oci push api.tar acme/default/api:1.4.0
  • Docker, Podman, BuildKit, crane, ORAS, Helm (oci://) and cosign (referrers API) work through the helper.
  • Multi-platform indexes, Helm charts, SBOMs and signatures are stored as plain OCI manifests.
  • Stock docker push sends each layer in one request, and Prego accepts at most 95 MiB in one request. prego oci push sends bigger layers in parts.
  • Kubernetes pulls with an imagePullSecret that holds a read-only API key (username = tenant). The console Connect page writes the YAML.
  • Grants use ecosystem = oci with read, publish and delete. One any grant covers images and crates.

Not in 1.0.0: public or anonymous images, /v2/_catalog, a pull-through cache, scanning or a signature policy (signatures are stored, not checked), webhooks, replication, and a kubelet credential provider. See the OCI quickstart.

Go modules

From 0.4.0. Prego serves private Go modules on go.prego.k8skill.com through the GOPROXY protocol. Public modules still come from proxy.golang.org. Go 1.24 or later.

shell
$ prego setup go --prefix go.acme.com --write   # GOPROXY, GONOSUMDB, GOAUTH
$ go get go.acme.com/core@v1.4.0
# publish from the git tree of a tag, never from the working directory
$ git tag v1.4.0
$ prego go publish --dry-run
$ prego go publish
  • GOAUTH='prego go-auth' gives Go a registry token for the Prego URL only. Write it with no word command in front.
  • GONOSUMDB holds only your module path prefixes. All other modules are still checked against sum.golang.org.
  • A module zip can be at most 300 MiB, compressed and uncompressed. From 0.5.0, prego go publish refuses a bigger module before it sends anything.
  • Versions are immutable. To withdraw one, add a retract line and publish a new version.
  • Grants use ecosystem = go with read, publish and delete, on the full module path.

For Go before 1.24, use prego exec -- go build ./.... An API key in a static .netrc is the last resort: from registry 1.6.0 it works only for a Go grant with read only whose switch "Allow this API key in .netrc" an admin turned on. See the Go quickstart.

npm packages

prego 0.6.0 and later connect npm, pnpm, Yarn and Bun to private scoped packages (@acme/core). All other packages still come from registry.npmjs.org.

shell
$ prego setup npm --scope @acme   # .npmrc with ${PREGO_NPM_TOKEN}, never a token
$ prego exec -- npm install
$ prego exec -- npm publish
  • Commit .npmrc: it holds the variable name only. prego exec or eval "$(prego npm-env)" gives the token.
  • CI can publish with npm trusted publishing, with no Prego tool and no stored secret.
  • Create the free organization @acme on npmjs.com too, against dependency confusion.

See the npm quickstart.

Release Variables

prego 0.8.0 and later read and push plain settings that go with a release: an API base URL, feature flags, a list of regions. A machine that can pull the release reads them with the same identity.

shell
$ prego env pull acme/releases/payments@1.4.0 --out release.env --expect sha256:9f2c...
$ set -a; . ./release.env; set +a
$ prego env push acme/releases/payments@1.4.0 --file release-vars.json   # replaces the whole set
  • Release Variables are plain text, readable by everyone who can pull the release. Do not store passwords, tokens or keys here.
  • Levels: tenant, namespace and version. The most specific level wins, key by key.
  • --expect pins the RFC 8785 hash of the merged set and exits with 3 if anything changed. prego env hash computes it offline.
  • Every value in the env output is in single quotes. History, rollback and diff keep each version.

See the Release Variables guide.

Adapters

prego 0.10.0 and later push and get AI model adapters: the fine-tuned layers (LoRA) of your AI models, on the Publisher plan. Your machines and your customers load them with their own identity. The base model stays on Hugging Face or in your own storage.

shell
$ prego adapter push ./out/support-bot acme/ml/support-bot:2026-11-14 --license LicenseRef-llama3.1
$ prego adapter get acme/ml/support-bot:2026-11-14 ./adapters/support-bot
python
from transformers import AutoModelForCausalLM
from peft import PeftModel
base = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3.1-8B-Instruct")  # from Hugging Face or a local folder
model = PeftModel.from_pretrained(base, "./adapters/support-bot")
  • vLLM: --enable-lora --lora-modules support-bot=./adapters/support-bot.
  • Only safetensors weights and text files. Pickle files (.bin, .pt) can run code when they load, so Prego does not accept them.
  • A license is required. A version is written one time only. prego adapter get checks the SHA-256 of each file.

See the Adapters quickstart.

Identity sources

In auto mode each tool uses the first source that is present, in this order. If that source fails, it stops. It never falls through to an identity you did not expect.

  • 1

    SPIFFE Workload API

    When SPIFFE_ENDPOINT_SOCKET is set. Fetches a JWT-SVID for the audience.

  • 2

    SVID file

    When PREGO_SVID_FILE is set. Reads a JWT-SVID, for spiffe-helper setups.

  • 3

    GitLab CI

    When PREGO_ID_TOKEN is set from id_tokens with aud: prego.k8skill.com.

  • 4

    GitHub Actions

    When the Actions OIDC variables are set. The workflow needs permissions: id-token: write.

  • 5

    Token file

    When PREGO_TOKEN_FILE is set. Kubernetes projected tokens, AWS or GCP workload identity.

  • 6

    API key

    When PREGO_API_KEY is set (prk_…). The STS takes the tenant from the key.

  • 7

    Login session

    From 0.7.0, after prego login, when none of the above is set. For laptops, never for CI.

Safety rules

  • Never prints, logs or writes a token to disk (except prego token, which prints one on purpose).
  • Sends subject tokens only over https. Plain http only to localhost, for tests.
  • Never follows an HTTP redirect, so a subject token cannot go to another host.
  • A prego login session is kept only in the OS keychain or the kernel keyring, never in a plain file. Docker never gets the session itself.
  • TLS checks are always on. For an on-prem TLS proxy, add its CA with PREGO_CA_FILE.
  • The full STS contract is public in PROTOCOL.md, so you can review it or write your own client.

Security

Report a vulnerability by email to security@k8skill.com. Do not open a public issue, and do not send real tokens. See SECURITY.md.
